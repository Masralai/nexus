# Spec: Nexus v1.1

Living spec for the post-v1 (M0–M5) release. Do not implement epics until this document is
human-approved. SDD gate: **Specify → Plan → Tasks → Implement**.

Supersedes the ambiguous “sandboxing in v1.1” bullet in PLAN.md §11; sandboxing is **v2**
(see Boundaries / Out of scope). Parent docs: [PLAN.md](../PLAN.md), [PRD.md](../PRD.md).

---

## Objective

Ship the smallest set of upgrades that make the BYOK coding harness usable for **long
sessions** and **first-time setup**, without reopening v1 architecture.

**Users:** developers who already run `harness run` / `resume` / `self-test` with env or
`~/.harness.json`.

**Why now:** v1 truncates tool results and keeps working-memory, but still blows the
context window on long agent loops; setup requires hand-editing JSON; adapter stream
shapes live only as inline strings in tests; there is no CI gate on `main`.

**Success looks like:**

- Long runs automatically compact when context pressure is high and keep making progress.
- A new user can run `harness init` and get a working `~/.harness.json` without reading PLAN.
- `bun test` + `tsc` run on every PR; adapter behavior is pinned to checked-in fixtures.
- A single-binary / bunx install path is documented and scripted (no brew tap yet).

## Code Style

Match existing modules: small functions, no speculative interfaces, `ponytail:` comments
only for deliberate shortcuts.

**Compaction trigger (illustrative):**

```ts
// src/engine/compact.ts — shape, not final API
export function shouldCompact(pct: number, threshold = 0.8): boolean {
  return pct >= threshold
}

export async function compactMessages(
  messages: Message[],
  cheap: Provider,
  keepRecent = 6,
): Promise<Message[]> {
  const tail = messages.slice(-keepRecent)
  const head = messages.slice(0, -keepRecent)
  // one non-streaming or short stream call → single "prior context" user message
  const summary = await summarize(cheap, head)
  return [{ role: "user", content: `[prior context]\n${summary}` }, ...tail]
}
```

**Init write (illustrative):**

```ts
// src/cli/init.ts — write config; never echo API keys back
export function writeHarnessConfig(path: string, cfg: { provider: string; model: string }): void {
  mkdirSync(dirname(path), { recursive: true })
  writeFileSync(path, JSON.stringify(cfg, null, 2) + "\n", { mode: 0o600 })
}
```

Naming: `compactModel` in JSON / `HARNESS_COMPACT_MODEL` in env; threshold
`compactThreshold` / `HARNESS_COMPACT_THRESHOLD` (default `0.8`).

## Testing Strategy

| Concern | Level | How |
|---|---|---|
| Compaction trigger + transcript rewrite | unit | `MockProvider` scripted summary; assert message shape + `contextUpdate` |
| Adapter streaming | unit + fixtures | Load `fixtures/providers/**`; same assertions as today’s inline SSE tests |
| `harness init` | unit | Temp dir as HOME; assert file contents + mode; no network |
| CLI wiring | thin | Flag parse / exit codes only where behavior is new |
| Real keys | manual only | `harness self-test` — never CI |

**Coverage expectation:** every new public function has one failing-first test (TDD at
seams). No coverage % gate.

**Always:** `bun test` and `bun run typecheck` green before merging an epic.

## Boundaries

**Always**

- Mock-first engine tests; no real API keys in CI or fixtures that embed secrets.
- Env overrides config for runtime keys and model selection.
- Incremental JSONL persistence remains the session source of truth after compaction
  (append a compaction marker or rewritten continuity — see Open Questions).
- Keep diffs small (~≤5 files per task).

**Ask first**

- Adding npm dependencies.
- Changing default compact threshold or default cheap model IDs.
- Publishing to npm / creating a Homebrew tap.
- Any sandboxing / seccomp / container work.

**Never**

- Commit API keys or `.harness.json` with secrets.
- Call real providers from automated tests.
- Expand v1.1 into keyring, SQLite, plugins, or sandboxing.
- Remove failing tests to go green.

## Success Criteria

### E1 — Fixtures + CI

- [x] OpenAI-compatible and Anthropic stream cases used in tests are loaded from
      `fixtures/providers/**` (not only inline template strings).
- [x] `.github/workflows/ci.yml` runs `bun test` and `bun run typecheck` on PR and `push` to
      `main`.
- [x] CI uses Bun; no real network calls to providers.

### E2 — `harness init`

- [x] `harness init` prompts for provider + model (and prints where to set env keys — does
      not require pasting keys into the file).
- [x] Writes `~/.harness.json` (or `HARNESS_CONFIG` path if we add it later — default home
      path only in v1.1).
- [x] Re-running init overwrites with confirmation or `--force`.
- [x] `bun test` covers write behavior with a temp HOME.
- [x] Runtime still prefers env over file (`loadConfig` unchanged precedence).

### E3 — Compaction

- [x] When estimated `pct >= compactThreshold` (default **0.8**), loop invokes compaction
      before the next provider call.
- [x] Cheap model from `compactModel` / `HARNESS_COMPACT_MODEL`; if unset, same provider
      with a documented smaller default per provider family.
- [x] Transcript becomes: one `[prior context]` message + recent tail (`keepRecent`,
      default **6**); working-memory still prepended each turn.
- [x] Emits `contextUpdate` after compaction; does not drop JSONL history of pre-compact
      turns already appended (see Open Questions for exact persistence shape).
- [x] MockProvider tests prove trigger, rewrite, and “continues after compact”.

### E4 — Installers

- [x] `package.json` script `build:compile` produces a runnable binary via
      `bun build --compile`.
- [x] README section: run via `bun`, compiled binary, and intended `bunx` usage.
- [x] No brew formula in this epic.

## Plan (implementation order)

```
E1 fixtures+CI ──┬──► E2 harness init ──┐
                 │                       ├──► E4 installers
                 └──► E3 compaction ─────┘
```

E1 first so compaction/init land behind a green CI gate. E2 and E3 are independent after
E1. E4 last (packaging/docs only).

**Risks**

| Risk | Mitigation |
|---|---|
| Compaction loses tool-call continuity | Keep recent tail large enough to include last tool round-trip; test with tool messages in tail |
| Cheap model misconfigured | Fallback: skip compaction once, emit `error` or log, continue with truncation-only |
| Init writes secrets by accident | Spec forbids storing keys in v1.1 init; document env vars only |
| Fixture drift from live APIs | Fixtures are contract tests; update deliberately when adapters change |

**Checkpoints:** after each epic — full `bun test` + `typecheck`; human ack before next epic
if behavior is user-visible (E2/E3).

## Open Questions

Resolve before or during the relevant epic (ask human if unsure):

1. **Persistence after compaction:** append a JSONL `compact` status line and keep full
   history on disk while the in-memory `messages` array is compacted — or rewrite?  
   **Default if unanswered:** keep full JSONL history; compact **in-memory only** for the
   next provider prompt (resume loads full history and may re-compact).

2. **Default cheap models:** e.g. `gpt-4o-mini` for openai-compatible, `claude-haiku-*`
   for anthropic — confirm IDs when E3 starts.

3. **Init and API keys:** confirm v1.1 init **never** writes keys (env-only), vs optional
   write-to-file with 0600.  
   **Default if unanswered:** never write keys.

4. **`HARNESS_CONFIG` path override:** needed for tests/init UX?  
   **Default:** tests set HOME; no new env until asked.
